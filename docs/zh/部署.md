# 部署（笔记本 → VPS，$0 → 便宜）

> 理念：先笔记本（私有、离线、$0），再一台便宜 VPS 跑单服务。
> 不需要 Kubernetes。一个 `api`、一个卷、一个 key。

## 笔记本（默认）

卖家日常模式。无 Docker、无网络、Mock LLM。

```bash
pip install -r requirements-seller.txt && pip install -e .
omni-one close --folder /tmp/my_shop --out ./close_today
omni-one serve --port 5003
```

检查：

- [ ] `omni-one doctor` 全绿。
- [ ] `close.json` 有黄金 `headline`（`Profit $169.09`）。
- [ ] API 在 `http://localhost:5003`，文档在 `/api/docs`。
- [ ] 健康检查：`/health`、`/readiness`、`/status`、`/ping`。指标：`/metrics`。

笔记本常用变量：

- `SELLER_LLM=mock`（默认，$0）。
- `ALLOWED_ROOT=/app/data/inbox` 只在 Docker/生产生效。

## Docker（单服务）

单 `api` 服务、`./data` 卷、Mock LLM。适合小 VPS。

```bash
docker build -t omni-one:latest .
docker compose up -d && curl -sf http://localhost:5003/health
```

`docker-compose.yml`: one `api` service, `./data` volume (`DUCKDB_PATH`, `AUDIT_PATH`,
`ALLOWED_ROOT=/app/data/inbox`), `SELLER_LLM=mock`. Drop seller files into `./data/inbox`.

中文解释：

- `docker-compose.yml` 只定义一个 `api` 服务（不是微服务舰队）。
- `./data` 卷持久化数据库（`DUCKDB_PATH`）、审计（`AUDIT_PATH`）和收件箱。
- `ALLOWED_ROOT=/app/data/inbox` 把文件夹关起来：结算读不到外面。
- `SELLER_LLM=mock` 保持 $0（无付费调用）。
- 把卖家文件丢进 `./data/inbox`，对它跑结算。
- `docker compose up -d` 后用 `curl -sf http://localhost:5003/health` 验证。

重建与看日志：

```bash
docker compose up -d --build
docker compose logs -f api
docker compose ps
```

## 生产加固

生成两个 32 字节密钥（一个给 API，一个给签名），以生产模式启动。

```bash
python3 -c "import secrets; print(secrets.token_hex(32))"  # twice
ENVIRONMENT=production VALID_API_KEYS=<32+> SECRET_KEY=<32+> docker compose up -d
```

Demo keys (`demo-key/test-key`) are rejected in production; `/admin/*` needs key;
uploads capped (5MB, type-checked, 60/min); folders jailed to `ALLOWED_ROOT`;
audit `verify()` proves tamper-evidence. See `SECURITY.md`.

中文检查单：

- [ ] 已开 `ENVIRONMENT=production`（无 key 直接拒绝，fail closed）。
- [ ] `VALID_API_KEYS` 32+ 字符，与演示不同。
- [ ] `SECRET_KEY` 32+ 字符，用 `secrets.token_hex(32)` 生成。
- [ ] 演示 key（`demo-key`/`test-key`）在生产会被拒绝。
- [ ] `/admin/*` 要求 `X-API-Key`/`Bearer`（见 `GET /api/v1/admin/services`、`POST /api/v1/admin/clear-cache`）。
- [ ] 上传限制（5MB、类型检查、60/min）。
- [ ] 审计 `verify()` 已验证。见 `SECURITY.md`。

## Cron：每天 7 点结账

```cron
0 7 * * * cd /path/to/omni-one && PYTHONPATH=src python3 -m omni_one.cli close --folder ./data/inbox --out ./close_$(date +\%F) >> ./close_cron.log 2>&1
```

说明：

- 把 `/path/to/omni-one` 换成你的真实路径。
- Docker 下 `--folder ./data/inbox` 须在 `ALLOWED_ROOT` 内。
- `--out ./close_$(date +\%F)` 每天一个文件夹（`close_2026-10-11`）。
- 某天早晨没包就看 `./close_cron.log`。
- v1.2 结合邮件（见 `docs/zh/路线图.md`）。

## 监控

Scrape `GET /metrics` (briefings/scenarios/closes/vision counters + `omni_one_up`).

中文：

- 用 Prometheus 每 15–30s 抓 `GET /metrics`。
- 计数器：briefings、场景、结算、视觉 + `omni_one_up`。
- `omni_one_up == 0` 或 7 点后 `closes_total` 不涨就告警。
- 留好 `./close_cron.log`，旧 `close_*` 归档到冷存/U 盘。
