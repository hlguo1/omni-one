# 事件处理 — 断货 / 1 星 / 费率暴涨 runbook

> 事件赢在第一个小时。每个 runbook 同一形状：**发现**（结账显示什么）→
> **分级**（ severidad 表）→ **行动**（限时编号步骤）→ **跟进**（不再复发）。
> 打印本页。警报一响就计时。

## 严重度（通用）

| Sev | 含义 | 响应时间 | 谁 |
|---|---|---|---|
| S1 紧急 | 正在*实时*亏钱（chargeback、#1 断货、账号警告） | < 1h | 你，放下一切 |
| S2 高 | 几天内会亏钱（2 天库存、1 星在涨浏览、费率跳） | < 4h | 你，今天 |
| S3 中 | 毛利侵蚀/慢出血 | 本周 | 排期块 |
| S4 低 | 观察，无动作 | 备注 + 下次复查 | 下次结账 |

## Runbook A — 断货（爆款马上归零）

**发现：** `reorder.csv` 显示 #1 `ORDER TODAY`（`days_left` < 3），
或 briefing 报警 `Stockout risk: X only N left, D days supply`
带引用 `[inventory.csv:N]`。

### 分级

| 信号 | Sev |
|---|---|
| top-3 `days_left` < 1 | S1 |
| 任一 `days_left` 1–3 | S2 |
| `days_left` 3–5 | S3 |
| 无库存文件/品名未匹配 | S2（盲 = 危险） |

### 行动（S1/S2，30 分钟盒）
1. **[0–5] 核数字。** 打开引用里的 `[inventory.csv:line]`。肉眼看下货架——`on_hand` 真的吗？（常见：在市集卖了 3 件忘减。）错就改 CSV，重跑结账。
2. **[5–10] 发 PO。** 复制 `po.txt`，填空，发出。要 **tracking + 分批发**，有部分现货就说“今天先发有的，剩下的 ASAP”。
3. **[10–15] 保护 Listing。** 若 `days_left` < 交期：涨价 10–15% 压速度 *或* 限购 *或* 停广告。暂停的 Listing 强过超卖（取消单伤排名 + 触发退款）。
4. **[15–20] 通知等货买家。** 问“货在哪”的 DM（该 SKU）先发模板 19（定制 ETA），*趁他还没气*。
5. **[20–30] 排备选。** 供应商手册 §5：主供应商 ETA > `days_left` 就今天给备选下试单。

### 跟进（48h）
- [ ] PO 有书面 ETA 确认？没有就升级（打电话）。
- [ ] Listing 保护还在？到货当天就撤（过期限购丢单）。
- [ ] 根因：交期滑了、速度爆了、还是盘点飘了？修*因*：固定 PO 日（如每周一）、波峰 SKU 降备货阈值、或 $20 扫码盘点习惯。

## Runbook B — 1 星评价 / 评价危机

**发现：** briefing `at_risk` 跳涨，结账 `reply_queue` 多一条 `review`
渠道行，或 scenarios 列出 `REVIEW_CRISIS` 带证据 `[reviews.csv:N]`。

### 分级

| 信号 | Sev |
|---|---|
| 爆款 1★ + 提安全/过敏/chargeback | S1 |
| 1–2★ 有损坏/晚到细节，< 24h | S2 |
| 1–2★ 模糊（“不喜欢”），较旧 | S3 |
| 3★ 建设性 | S4（感谢 + 静静改） |

### 行动（S1/S2，45 分钟盒）
1. **[0–5] 先读别气。** 打开精确的 `[reviews.csv:line]`。记下*可验证*的主张（碎了？晚了？发错了？）。能定位订单就查引用。
2. **[5–15] 公开回（模板 08）。** 感谢 + 道歉 + 说修复 + 邀私信。绝不：争事实、公开提退款（招敲诈）、回两遍。一回就停，别盯帖。
3. **[15–25] 私信（模板 05/06）。** 1 小时内给*选择*（补发 OR 退款）。带引用。S1 先给退款——这里速度胜过毛利。
4. **[25–35] 为*下个*买家修因。** 破损 → 今天加打包步骤（新打包拍照）。晚到 → 查承运商批次。发错 → 现在就重贴货架标签，别“以后”。
5. **[35–45] 记一笔。** 一行：日期、SKU、主张、真/假、成本（退款 $X / 重发 $Y）、修复。一季度同样三行 = 产品/流程要改，不是运气差。

### 跟进（7 天）
- [ ] 买家改评价了吗？（礼貌问*一次*，模板 15。永远不要花钱买改评——会封号。）
- [ ] 修复 holding 住了吗？该 SKU 2 周零复发 = 关闭。
- [ ] 若主张是假的/恶意的：带证据链举报（`replies.txt` + 订单引用）。翻篇——二十个 5 星里的一条差评转化*更好*（真实感效应）。别为它 nuk 掉 Listing。

## Runbook C — 费率暴涨 / 毛利崩塌

**发现：** 结账 `money_leaks` 出现 `fee_creep`（手续费 ≥ GMV 12%），或
标题行毛利周环比掉 > 5 个点且 GMV 差不多，或某
渠道宣布调费。

### 分级

| 信号 | Sev |
|---|---|
| 综合毛利 < 0%（每单倒贴） | S1 —— 今天停付费流量 + 暂停最差 SKU |
| 综合毛利 0–10% 持续 2+ 周 | S2 |
| 某渠道宣布涨费 | S3（本周建模） |
| 运费漂移（趋势 +$1/单） | S3 |

### 行动（S1/S2，60 分钟盒）
1. **[0–10] 核数学。** `close.csv` A 节：爆的是 `fees`、`shipping` 还是 `cogs`？各有主人（渠道、承运商、供应商）。别找错人谈。
2. **[10–20] 手续费 → 调价或换渠道。** 经验：需涨价 ≈ `fee_delta / (1 − fee_rate)`。$28 涨 2 个点 ≈ +$0.60——凑 +$1 赚差价。或切量：Etsy 6.5%+$0.20 vs Shopify 2.9%+$0.30 vs Amazon 15%——先切*下* 10 单，别动历史。
3. **[20–30] 运费 → 重称。** 称打包后整箱（不是产品）。80% 的“费率暴涨”其实是体积重或分区漂移。修法：箱子改小、切到阈值下 tracked-lettermail，或包邮并入价（转化一般能 cover）。
4. **[30–40] COGS → 供应商复核。** 供应商手册 §3：无通知 +5% = 48h 内发邮件。top-3 SKU 的 COGS > 零售 45% = 调价 + 议价并行。
5. **[40–60] 砍或救最差卖家。** `kpis.worst_seller` + `listing_fixes`：清仓（回现金）、打包（提 AOV）、或下架（止血）。多愁善感不是策略。

### 跟进（30 天）
- [ ] 毛利回 10% 线上连续 2 周？
- [ ] 调价站住了吗（转化没崩）？改价后看 14 天单量；腰斩就回滚。
- [ ] 费率盯 habit：每次结账瞟一眼 `money_leaks`（5 秒）。结账负责看；你负责瞟。

## 跨事件规则

1. **一次只救一个。** 断货 + 1 星 + 费率暴涨一起来？顺序：断货（收入停了）→ 1 星（名声）→ 费率（毛利）。说出来。
2. **边做边写。** 每个动作旁边贴引用。未来的你（和会计、和渠道申诉团队）要这条链。
3. **一切限时。** 明天的完美回复输给 2 小时内的良好回复。SLA 就是产品。
4. **复盘最多 5 行：** 爆了什么、做了什么、花了多少、改什么、何时验。跟当月结账放一起。
5. **知道何时不是事件。** 单个 S4、毛利 ±2 点内晃、周二慢——记一笔，合电脑，打包去。系统在工作；让它转。
