# 晨间例行 — 5 分钟每日结账（7 天上手计划）

> **目标：** 每天早上，在打包任何包裹之前，你就知道
> （1）昨天到底赚了多少钱，（2）什么会断货，
> （3）谁现在很生气。一条命令，离线，$0：
>
> ```bash
> omni-one close --folder ~/my_shop --out ./close_today
> ```
>
> 你会得到 `close.json` + `close.csv` + `reorder.csv` + `replies.txt` + `po.txt`。
> 把它们打印出来，或者只读**标题行**——为咖啡因不足的大脑写的一行。

## 标题行解读

```
Profit $169.09 (61.7%) · $102.75 at risk in 3 angry messages · 1 reorder(s) TODAY · 0 leak(s) to plug
```

| 片段 | 含义 | 来源 |
|---|---|---|
| `Profit $169.09 (61.7%)` | 真实利润 = GMV − 手续费 − 运费 − COGS，再加毛利率 | 订单 CSV + 供应商发票 |
| `$102.75 at risk in 3 angry messages` | 退款敞口 ≈ 3 × AOV，来自未回复的投诉 | DM + 1–2★ 评价 |
| `1 reorder(s) TODAY` | 剩余 < 3 天供应的 SKU | 销量速度 vs 现有库存 |
| `0 leak(s) to plug` | 手续费/运费/毛利异常 | 渠道费率计算 |

每个数字都引用 `[file:line]`。如果某个数字没有引用，不要信——
去修源文件，而不是修表格。

## 5 分钟仪式（每天）

- [ ] **0:00–0:30 — 跑结账。** `omni-one close --folder … --out …`。大声读出标题行。
- [ ] **0:30–2:00 — 先回消息。** 打开 `replies.txt`。复制粘贴草稿 #1，个性化改一句话，发送。趁烧水重复。规则：**P0（退款/未到/破损）2 小时内必回，无例外。** 见 `03-回复手册.md`。
- [ ] **2:00–3:30 — 补货。** 打开 `reorder.csv`。凡是 `ORDER TODAY` → 今天就把 `po.txt` 草稿发给该供应商。凡是 `this week` → 记到日程。见 `02-供应商手册.md`。
- [ ] **3:30–4:30 — 堵一个漏。** 如果 `money_leaks` 非空，做最便宜的修复（通常：某 SKU 涨价 $1，或把某 SKU 移出高费率渠道）。记下来。
- [ ] **4:30–5:00 — 归档。** 把当天的导出移到店铺文件夹，给台账加一行（见 `04-会计交接.md`）。

## 7 天上手计划

### 第1天 — 放下文件夹（15 分钟，一次性）
- [ ] 创建 `~/my_shop/` 并放入：Shopify/Etsy/Amazon 订单导出、`inventory.csv`、评价导出、DM 导出（`.txt` 或 `.json`）、供应商发票（照片或 `.txt`）。
- [ ] 运行 `omni-one briefing --folder ~/my_shop`。确认 GMV 大致正确（与渠道后台差异 5% 以内）。
- [ ] 运行 `omni-one close --folder ~/my_shop --out ./close_day1`。每个文件读一遍。先别行动——只校准信任。
- [ ] **完成标准：** 标题行利润与你的预期差异不超过 20%。

### 第2天 — 只回消息
- [ ] 跑结账。只做回复队列。把每条 P0 草稿发掉（要改过，不能盲发）。
- [ ] 数已发送 vs 队列长度。目标：P0 清零。
- [ ] **完成标准：** 回复队列为空，或每条剩余都有跟进日期。

### 第3天 — 供应商
- [ ] 跑结账。读 `02-供应商手册.md` 第 1–2 节。
- [ ] 从 `po.txt` 发出第一张真实 PO（或确认库存健康——也是成果）。
- [ ] 在本子上记下 top 3 SKU 的单位成本。这就是你的 COGS 圣经了。
- [ ] **完成标准：** 发出一张 PO，或有书面确认无需补货。

### 第4天 — 手续费与漏损
- [ ] 跑结账。打开 `close.csv` 的 `money_leaks` 节。
- [ ] 算出各渠道费率（Etsy ≈ 6.5%+$0.20 · Shopify ≈ 2.9%+$0.30 · Amazon ≈ 15%）。如果综合费率 > GMV 的 12%，挑一个 SKU 调价或换渠道。
- [ ] **完成标准：** 能凭记忆说出费率，误差 1 个点以内。

### 第5天 — 全流程计时
- [ ] 计时跑完整仪式。目标：除发消息外 5 分钟内。
- [ ] 跑一次 `omni-one scenarios --folder ~/my_shop`，读 top 3 决策。这是明天的工作，不是今天的。
- [ ] **完成标准：** 结账 → 回复 → 补货 → 堵漏 → 归档，挂钟 30 分钟内。

### 第6天 — 会计包
- [ ] 按 `04-会计交接.md` 对账步骤 1–4，过一遍本周的结账。
- [ ] 把本周的 `close.csv` + `reorder.csv` 发给会计（或未来的你）。
- [ ] **完成标准：** 一周的结账与银行对账差异在 $5 以内。

### 第7天 — 事件演习
- [ ] 从 `05-事件处理.md` 挑一个 runbook（断货、1 星、费率暴涨）干走一遍——找引用、写消息、算修复价。
- [ ] 写下你的个人阈值（备几天货？毛利底线多少？）。
- [ ] **完成标准：** 三个 runbook 不看理论也能跑。

## 检查表

### 每日（塑封这张）
- [ ] 跑了结账，读了标题
- [ ] 所有 P0 回复 < 2h 发出
- [ ] ORDER TODAY 的 PO 发出
- [ ] 堵了一个漏
- [ ] 文件已归档

### 每周（周五，20 分钟）
- [ ] 7 次结账已对账，GMV vs 渠道后台 ±2%
- [ ] 催供应商 ETA（下单 > 7 天无 tracking 的）
- [ ] 列出呆滞库存（0 销量 + 5+ 件 → 清仓草稿）
- [ ] 对照费率变化复核价格
- [ ] 备份：复制 `~/my_shop` 到 U 盘/第二台机器

### 每月（第一个周一，1 小时）
- [ ] 当月 `close.csv` → 会计包（`04-会计交接.md`）
- [ ] 更新供应商记分卡（价格、ETA、不良率）
- [ ] 最差卖家决策：砍掉、打包或清仓
- [ ] 毛利底线检查：综合真实毛利 ≥ 10%？否则看漏损 playbook

## 排障

| 症状 | 可能原因 | 修法 |
|---|---|---|
| 利润看起来太高 | 缺供应商发票 → COGS 少算 | 把发票 `.txt`/照片丢进文件夹 |
| 利润看起来太低 | 发票重复（`.jpg` + `.jpg.txt` + `.txt`） | 结账自动去重相同内容；对比 briefing 里 `files_ingested` vs `files_seen` |
| `reorder.csv` 为空但货架空了 | 订单与库存品名不一致（`Tote` vs `Tote Bag Handmade`） | 改名对齐；匹配是模糊的，但精确最保险 |
| 回复队列为空但客户还在抱怨 | DM 导出的是截图不是文本 | DM 导出为 `.txt`/`.json`，或粘贴文本到 `instagram_dm.txt` |
| 手续费看起来不对 | 文件名误判渠道 | 订单文件命名 `shopify_*`、`etsy_*`、`amazon_*` |
| 分号 CSV 被忽略 | 本地导出（`;` 分隔） | 已支持——Sniffer 会处理；若某文件 0 行，检查能否以 UTF-8 打开 |
| 乱码（`ï»¿`） | Excel 的 BOM 头 | 已支持（UTF-8-SIG）；测试时可用 `evals/generate.py --help` 边界用例升级 |

## 唯一规则

> **无引用，不行动。** 结账拒绝编造任务。如果它让你补货，
> 它会给你看 `[inventory.csv:2]`。如果它让你回复，
> 它会给你看 `[instagram_dm.txt:4]`。按这个标准要求它——也按同样标准
> 要求你的供应商、渠道和会计。
