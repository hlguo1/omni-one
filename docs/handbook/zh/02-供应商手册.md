# 供应商手册 — PO、议价与 COGS 台账

> 供应商是仅次于渠道手续费的第二大成本，也是唯一能用人话
> 谈价的成本。本手册把每日结账的 `reorder.csv` + `po.txt`
> 变成准时到货、价格可证的采购单。

## 1. 怎么读 `reorder.csv`

```
product,on_hand,sold_7d,daily_velocity,days_left,reorder_qty_14d,supplier,urgency,citation
Tote Bag Handmade,2,6,0.86,2.3,10,Acme Textiles,ORDER TODAY,[inventory.csv:2]
```

| 列 | 定义 |
|---|---|
| `on_hand` | `inventory.csv` 里现在的件数 |
| `sold_7d` | 订单文件最近 7 天卖出的件数 |
| `daily_velocity` | `sold_7d / 7` |
| `days_left` | `on_hand / daily_velocity`（999 = 无销量） |
| `reorder_qty_14d` | `ceil(速度 × 14 − on_hand)`，最低 0 |
| `urgency` | `ORDER TODAY`（< 3天）· `this week`（< 5天）· `watch` |

**备货策略：** 14 天。为什么 14？覆盖小供应商平均交期
（7–10 天）再加一个超卖的周末，又不把现金锁死在
呆滞库存里。如果供应商 3 天到货，降到 7（改 `seller_close.py` 里 `COVER_DAYS`）。
如果海外发货（20+ 天），升到 30——
并找备选供应商（第 5 节）。

## 2. PO 话术（复制粘贴，再填括号）

### 2a. 标准补货（自动生成为 `po.txt`）

```
Subject: Reorder request — [SUPPLIER]

你好 [NAME]！

请为 [YOUR SHOP] 发以下货：
  - Tote Bag Handmade: 10 件（现有 2 件，还剩 2.3 天）[[inventory.csv:2]]

请确认价格 + ETA。上次发票号已按记录引用在上。

谢谢！
[YOUR SHOP]
```

规则：永远引用上次发票，永远**同一封邮件要价格 + ETA**
（只跑一趟，不跑两趟），数量永远写数字，不写“再来点”。

### 2b. 新供应商首单

```
Subject: First order + samples — [YOUR SHOP]

你好 [NAME]！我是 [SHOP]，在 [CHANNEL] 每月 [X] 单。
想先从以下开始：
  - [PRODUCT]：[QTY] 件，按 [TARGET UNIT PRICE]
问题：
  1. [QTY] 和 [2×QTY] 的单价？
  2. 到 [CITY] 的交期？不良/退货政策？
  3. 能寄 1 件样品吗？运费我付。
样品过关，本周就下首单。
谢谢！[YOU]
```

### 2c. 催晚到的货（7+ 天，无 tracking）

```
Subject: Checking ETA — PO of [DATE] ([QTY]× [PRODUCT])

你好 [NAME]！[DATE] 的 PO 还没到，我们距
断货还有 [N] 天（[citation]）。今天能确认 tracking 吗？
如果 [DATE] 前发不出，请现在告诉我，我好拆单。
谢谢！[YOU]
```

### 2d. 不良批次

```
Subject: Defect batch — [PRODUCT], [N] units ([DATE] delivery)

你好 [NAME]！[DATE] 批次 [QTY] 件里有 [N] 件 [DEFECT]。
照片附上。按你们的退货政策，我想要[补发/退款 $X]。为避免断货，
 replacements 需在 [DATE] 前到。
今天能确认吗？谢谢！[YOU]
```

## 3. 议价阈值

**任一**触发就议价（或比价）——每月检查：

| # | 阈值 | 怎么发现 | 动作 |
|---|---|---|---|
| 1 | 单价无通知涨 > 5% | 新发票行 vs COGS 圣经（§4） | 48h 内发邮件，引用旧价 + 发票行 |
| 2 | 任意 top-3 SKU 的 COGS > 零售价 45% | `close.csv` cogs vs 单品 GMV | 零售涨 $1–2 *或* 议价 *或* 换源 |
| 3 | 一季度交期跳 2 次 | 你的 PO 台账（发出 vs 到达） | 该 SKU 双源（第 5 节） |
| 4 | 某批次不良率 > 3% | 评价/DM 报损 + 你的 QC 数 | 不良邮件（§2d）+ 5% 折扣或免费补发 |
| 5 | ORDER TODAY 供应商 > 72h 失联 | 你的已发送 | 转电话升级；启动备选试单 |
| 6 | 综合真实毛利连续 2 周 < 10% | 结账标题行 | 全成本复核：手续费（晨间例行 §4）、COGS、运费——按此顺序 |

### 议价话术

```
Subject: Price review — [PRODUCT] ([QTY]/month run-rate)

你好 [NAME]！我们连续 [N] 个月每月订 [QTY] 件（上次：
[invoice citation]）。你们最新报价 $[NEW]，而我们的工作
成本是 $[OLD]（发票 [citation]）。
我想继续跟你做——能到 $[TARGET] 吗？我可以承诺
[QTY] 件/月连订 3 个月 + [X] 天内付款。
如果不行我理解——我就得把量分出去了。
谢谢！[YOU]
```

比哀求好用的机制：**承诺量**（哪怕小）、
**更快付款**（7 天胜过 30 天）、**规律下单**（每月同一天）。
供应商给可靠性打折，不给同情心打折。

## 4. COGS 台账（圣经）

留一个文件——纸也行——每 SKU 一行：

```
SKU     Product            Supplier      Unit $  Since       Lead time  Notes
TB001   Tote Bag Handmade  Acme Textiles 4.00    2024-09-10   8d        canvas+strap
CM002   Ceramic Mug        Clay Co       6.10    2024-09-10   6d
```

结账怎么算 COGS（讲一次，以后永远指这里）：

1. 供应商 `.txt` 发票行形如 `NAME QTY x UNIT TOTAL`
   （如 `Tote Bag Canvas 50 x 4.00 200.00`）建成按物料的单价目录。
2. 每条订单按品名模糊匹配目录 → COGS += 单价 × 件数。
3. 匹配不上 → 按该行 GMV 的 30%（有文档的启发式）。
4. 一张发票都没有 → 按最小发票总额的 25%（兜底）。

**你的工作：** 让第 2 步永远命中——发票品名用词与 Listing 标题保持重叠
（`Tote`、`Mug`、`Print`、`Scarf`）。共用一个词就够。
每周看 `close.json → kpis.cogs`：没调价却跳了，就是某发票行匹配断了。

### 发票卫生
- 每次到货一个 `.txt`：供应商名，每物料一行 `QTY x UNIT TOTAL`，
  `Shipping`，`Total $X`。照片发票也行（OCR），但文本最准。
- 不要同时留照片和手打版且数字不同——
  结账只去重*相同*文件，不去重*冲突*文件。
- 命名：`supplier_invoice_YYYY-MM-DD.txt`（日期方便排序）。

## 5. 双源（一个人的保险）

只针对 #1 爆款：
- [ ] 找备选供应商（Etsy 批发、Alibaba 样品、本地手作）。
- [ ] 试单：最小量，记录单价 + 交期 + 不良数。
- [ ] 分单规则：备选连续 2 次干净交付后，主 70% / 备 30%。
- [ ] 若主供应商交期超过 `reorder.csv` 的 `days_left`，立刻反转比例。

成本：每季度多一单样品。回报：再也不因别人的物流丢掉爆款。

## 6. 每月供应商记分卡（10 分钟）

| 供应商 | 单数 | 准时% | 不良% | 单价Δ | 结论 |
|---|---|---|---|---|---|
| Acme Textiles | 3 | 100 | 0 | +0% | 保留 |
| Clay Co | 2 | 50 | 5% | +6% | 议价/试备选 |

任何供应商连续两月准时 < 70% 或不良 > 5% 就换掉。
你的小店没钱补贴别人的混乱。
