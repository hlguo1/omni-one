# 会计交接 — `close.csv` 字段字典 + 对账

> 你的会计不要看板，要能对上银行、有单据的总数。每日结账正好产出：
> `close.csv`（钱）、`reorder.csv`（库存动作意图）、`replies.txt`（退款
> 证据链）。本页是字典 + 月度例行。

## 1. `close.csv` 字段字典

`close.csv` 有四个节。第 1 节是标题行（`DAILY CLOSE,
<date>, <headline>`）。然后：

### A 节 — `metric,value`（台账行）

| metric | 类型 | 定义 | 来源文件 |
|---|---|---|---|
| `gmv` | USD，2位 | 成交总额：订单行总额之和 | `shopify_orders.csv`、`etsy_settlement.csv`、`amazon_payout.csv` |
| `fees` | USD，2位 | 渠道手续费：按行解析，否则估算（Etsy 6.5%+$0.20 · Shopify 2.9%+$0.30 · Amazon 15% · 其他 8%） | 同上订单文件 |
| `shipping` | USD，2位 | 每单已付/已收运费 | 同上订单文件 |
| `net` | USD，2位 | `gmv − fees − shipping` | 计算 |
| `cogs` | USD，2位 | 销货成本，按供应商发票分摊到件（见 §3） | `supplier_invoice_*.txt`（+ OCR  sidecar） |
| `true_profit` | USD，2位 | `net − cogs`。**最关键**的数。标杆：演示店 = $169.09 | 计算 |
| `margin_pct` | %，1位 | `true_profit / gmv × 100`（gmv=0 时为 0） | 计算 |
| `orders` | int |  Ingest 的订单行数 | 订单文件 |
| `aov` | USD，2位 | `gmv / orders`（无订单时 0） | 计算 |
| `best_seller` | 对象 | `{product, qty, gmv}` 按件数 top | 计算 |
| `money_at_risk_usd` | USD，2位 | `len(reply_queue) × aov`——未回投诉的退款敞口 | DM + 评价 |

**会计可验的不变量：** 每行 `true_profit ≤ gmv`，
永远成立。（evals 按店铺断言；见 `evals/run.py`。）一旦违反，
数据坏了——重导渠道 CSV。

### B 节 — `do_today_n,do_today`（动作，不是钱）
三行：回复工作量、top 补货、top 漏损。仅提示；不入账。

### C 节 — reorder 块
`product,on_hand,sold_7d,days_left,reorder_qty_14d,supplier,urgency,citation`
——结账时刻的库存位。`reorder_qty_14d` 是*采购意图*，
不是已入账费用。供应商发票到才入账。

### D 节 — 漏损块
`leak,amount_usd,note,evidence`——费率 creep / 运费亏损 / 毛利下滑
带金额。`amount_usd` 可空（如单均运费亏损）；`note` 写明细。

## 2. `reorder.csv` + `replies.txt` + `po.txt`

| 文件 | 会计用途 |
|---|---|
| `reorder.csv` | 库存意图：订了什么、为什么（每行引用）。跟采购发票放一起。 |
| `replies.txt` | 退款/chargeback 证据链：客户原话 + 你的草稿 + 引用。贴到争议交易上。 |
| `po.txt` | 发出的 PO 邮件原文。把供应商确认回执放旁边。 |
| `close.json` | 机器可读的一切（KPI、完整 reorder、回复队列、漏损、PO 草稿）。存 12 个月。 |

## 3. COGS 怎么算（讲一次，以后永远指这里）

1. 每条供应商 `.txt` 形如 `MATERIAL QTY x UNIT TOTAL`
   （例：`Tote Bag Canvas 50 x 4.00 200.00`）登记一个单价。
2. 每条订单按品名模糊匹配目录；COGS += 单价 × 件数。
3. 匹配不上回退到该行 GMV 的 30%（隐式标记：COGS
   尾数很圆——整月都这样就要查）。
4. 一张发票都没有 → 按最小发票总额的 25%（应急兜底）。

**记账含义：** `close.csv` 的 COGS 是*当天组合的分摊销货成本*，
适合看毛利。报税仍用实际采购发票（收付实现）——结账讲
毛利故事；发票鞋盒讲税务故事。两者月度应收敛到几个点以内。
对不上就是某供应商行匹配断了（改名漂移）——见供应商手册 §4。

## 4. 对账步骤（月度，30 分钟）

**需要：** 当月 `close.csv`、渠道 payout 单
（Shopify/Etsy/Amazon）、银行流水、供应商发票。

- [ ] **第 1 步 — 加总。** 把当月 `close.csv` A 节的 `gmv`、`fees`、`shipping`、`true_profit`
      加起来。（one-liner：
      `awk -F, '/^(gmv|fees|shipping|true_profit),/{s[$1]+=$2} END{for(k in s)print k,s[k]}' close_*/close.csv`。）
- [ ] **第 2 步 — GMV 对渠道。** 月 GMV 应与渠道后台 ±2% 内。差距大 → 漏导出（一周订单
      没丢进文件夹）或文件重复。
- [ ] **第 3 步 — 手续费对 payout。** `fees` 应与
      （渠道销售额 − 渠道 payout）±3% 内。导出缺费率列时 Etsy/Shopify 用
      公式估算，±3% 正常；±10% 说明某费率列解析错——查表头名。
- [ ] **第 4 步 — 利润对银行。** `true_profit − 供应商付款 −
      已发退款` 应与对公户变动 ±$5–10 对上
      （timing：payout 晚 2–5 天；逐月显式结转 lag）。
- [ ] **第 5 步 — 退款审计。** 数 `replies.txt` P0 vs 银行退款。
      每笔退款要有引用（客户消息）。孤儿 →
      改掉 DM 导出习惯。
- [ ] **第 6 步 — 签字。** 写一行：`2024-09: GMV $X, profit $Y,
      reconciled ±$Z — initials`。跟当月结账放一起。

## 5. 常见差异与修法

| 差异 | 原因 | 修法 |
|---|---|---|
| GMV 比后台低 5–15% | Etsy `price` 列是单价，文件 qty>1（或反之） | 重导行总额；生成器写总额（见 `evals/generate.py`） |
| Shopify 行手续费 ~0 | 导出缺费率列 → 按 2.9%+$0.30 估 | 运营够用；报税用 payout 单，不用估算 |
| COGS 逐月跳 | 新供应商措辞打断模糊匹配 | 发票与 Listing 对齐一个词（供应商手册 §4） |
| 利润 > GMV（永远不正常） | 脏行（负手续费解析成 credit） | 触发 eval 不变量——找到该行，修 CSV，重跑结账 |
| `money_at_risk` 巨大 | 旧 DM 一直堆在文件夹 | 每月归档已处理的 DM；文件夹是*队列*，不是档案馆 |
| 分号/BOM 文件 0 行 | Excel 本地导出 | 解析器已支持；确认文件能以 UTF-8 打开且文件名含 `order/shopify/etsy/amazon` |
