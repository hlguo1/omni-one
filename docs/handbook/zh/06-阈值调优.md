# 06 — 阈值调优指南

Seller OS 的所有数字都来自一张表：`src/omni_one/packs/seller_scenarios.py` 的
`SCENARIO_THRESHOLDS` + `src/omni_one/packs/seller_close.py` 的 `COVER_DAYS`/`STOCKOUT_DAYS`。
按店铺调优，并在结算中注明修改原因。

| 参数 | 默认值 | 调高当 | 调低当 |
|---|---|---|---|
| `stockout_days` | 5.0 | 供应商交期 > 7 天 | 数字商品 / 按需打印 |
| `COVER_DAYS` | 14 | 交期长、爆款 | 现金紧、仓储小 |
| `fee_creep_pct` | 12.0 | 亚马逊为主（15% 正常） | 只做 Shopify（应在 3% 左右） |
| `shipping_loss_pct` | 20.0 | 满 $X 包邮策略 | 轻小件 |
| `margin_low_pct` | 10.0 | 手工高溢价（目标 50%+） | 薄利多销转售 |
| `dm_backlog_count` | 3 | 一人经营、周末 | 团队客服、2h SLA |
| `price_mismatch_pct` | 5.0 | 多币种 | 同币种多渠道 |
| `dead_stock_min_qty` | 5 | 仓储贵 | 小配件 |

流程：只改一个参数 → `omni-one close --folder <店铺> --out /tmp/close_after` →
对比 `reorder.csv` + `close.csv` → 若 `money_at_risk` 下降且不产生垃圾补货单则保留。
把参数 + 原因记入 `close.json` 给会计。永远不要为了掩盖漏损而调参——佣金是事实，定价才是杠杆。
